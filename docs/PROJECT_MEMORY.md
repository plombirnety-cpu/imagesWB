# Память проекта Print Factory

## Актуально на 2026-07-26

- Радар теперь автоматический:
  - сам запускается после старта и далее каждые 3 часа;
  - бесплатно собирает RU Google Trends и открытый мемный каталог/каналы
    Telegram;
  - сохраняет темы в `radar_seeds`, историю фоновых проходов в
    `collector_runs`, не допускает наложения запусков;
  - TikTok discovery, метрики и комментарии реализованы через Bright Data;
  - для живого TikTok-поиска в production нужен одноразовый секрет
    `BRIGHTDATA_API_TOKEN`; ключ не хранится в БД/UI/git;
  - повторения новых слов считаются по TikTok-комментариям с уникальными
    авторами, а не по общей частотности слов в Telegram-постах;
  - ручные ссылки оставлены только в свёрнутой диагностике.
- Автоматический API: `GET /api/radar/collector/status`,
  `POST /api/radar/collector/run`, `GET /api/radar/seeds`.
- Кураторские Telegram-seed имеют приоритет при TikTok discovery. Seed не
  считается доказательством новизны: жизненный цикл по-прежнему требует даты,
  независимого источника и/или измеренной скорости.
- Радар мемов теперь должен воспринимать повтор той же ссылки как повторный замер,
  а не как новый ролик и не как бесполезный дубликат. История живёт в
  `metric_snapshots`; отрицательная динамика от уменьшившихся счётчиков запрещена.
- Главный сигнал раннего роста — измеренная скорость за несколько замеров:
  просмотры/лайки/репосты/комментарии в час. Поправки короче пяти минут не должны
  раздувать `velocity_score`.
- Для старого мема новый скачок означает `RESURGENCE`, но никогда не `NEW`/`RISING`.
- Панель принимает пакет до 100 сигналов через JSON и показывает число замеров и
  скорость. Batch API допускает частичный успех.
- Официальный Display API не даёт глобальную выдачу, а Research API не подходит
  коммерческому раннему мониторингу. Поэтому TikTok подключён через разрешённый
  API провайдера данных, а не нестабильный браузерный скрейпинг.
